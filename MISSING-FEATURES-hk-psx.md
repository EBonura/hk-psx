# Hollow Knight original feature census, 11 October 2026

This is an incomplete semantic census, not an exhaustive gameplay parity claim. Every one of the original Windows installation's 501 BuildSettings scene files was decoded, together with resources.assets. Original files were read only. Sharedasset external prefabs and localization remain outside this initial scan. The resources.assets UI object resources.assets:20590, VisualTreeAsset, could not decode because ReferencedObject fields are unsupported; this is an explicit source-completeness blocker. The archive preserves inactive objects, alternate encounters and source object hashes rather than discarding them.

The generated source archive and evidence reports are outside Git under `/Users/ebonura/Library/Application Support/PSoXide-perf/work/hk-census-finalise-2026-10-11/`. `original/source-objects.jsonl` records every scanned GameObject and MonoBehaviour. `report/feature-contracts.jsonl` joins source IDs to cooked admissions and audited implementation evidence. `report/semantic-features.jsonl` groups only explicitly typed original contracts. These files are regenerated, not a fixed missing list.

## Count units and outstanding audit

The initial semantic table finds 136 authored enemy journal family keys, 36 boss statue name keys, 222 NPC conversation instances, 12 enabled ability write variants, 40 original inventory charm IDs, 45 selected pickup write variants, 4,534 interactable component instances, 480 scenes with SceneManager settings and 1,119 transition component instances. These units overlap and cannot be summed into a total of unique gameplay features. Journal keys do not prove enemy classification; statues include Godhome variants; SceneManager includes menu, dream, test and additive scenes. The semantic table does not yet resolve all alias relationships or acquisition reachability.

Implementation and exercise counts require reviewed evidence. One source contract currently has a validated implementation subset, the Tutorial_01 Crawler's WalkLeftRight controller. Its original behaviour has no bound journey assertion and receipt, so it is implemented but unexercised. The complete current component-contract report contains 37,925 rows: 33,686 missing scene admission, one implemented subset without exercise proof, and 4,238 requiring semantic review. These are component instances, not unique enemies or features. HealthManager alone is never evidence that an object is an enemy. Merely visiting a scene or asserting aggregate damage is never evidence that every original contract was exercised.

The runtime evidence registry validates original object hashes, implementation file hashes and exact reviewed symbols. Changes invalidate the audit. Exercise claims are currently disabled entirely until structured source-contract, disc and journey hashes plus exact assertion PASS and matching FAIL exclusion can be validated. No semantic feature has such a proof yet. `semantic_census_complete` remains false.

## Reproduction

Run the scanner with the original Windows hollow_knight_Data directory and a scratch output directory. Then run `report ORIGINAL_OUTPUT COOKED_PORT_ROOT REPORT_OUTPUT tools/census/registry.json` and `semantic ORIGINAL_OUTPUT REPORT_OUTPUT` using the standalone Rust crate in tools/census. Keep archive output outside the checkout. The grant resolver fixtures verify that unused prefab branches do not become grants and unresolved runtime variable values remain unknown. The original installation is never changed.
